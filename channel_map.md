# Transport Channel Map Specification

В данной спецификации определены правила разделения задач между протоколами **REST (HTTP)** и **WebSocket (WS)**, а также сценарии аварийного переключения (Fallback).

---

## 1. Общие принципы разделения каналов

| Критерий | REST (HTTP / HTTPS) | WebSocket (WS / WSS) |
| :--- | :--- | :--- |
| **Характер взаимодействия** | Request-Response (Запрос-Ответ) | Full-Duplex Realtime Streams |
| **Использование** | Инициализация, авторизация, загрузка истории, fallback отправка | Мгновенный push входящих сообщений, живые статусы доставки |
| **Гарантии** | Синхронное подтверждение приема сервером | Двунаправленный обмен в реальном времени с легким Keepalive |

---

## 2. Разделение операций по каналам

### 2.1 Операции только через REST API

```
POST /api/v1/auth/login          --> Первичный входе и получение JWT/Session token
POST /api/v1/auth/refresh        --> Обновление просроченного токена
GET  /api/v1/capabilities        --> Запрос поддерживаемых версий протокола и фичей сервера
GET  /api/v1/sync/backlog        --> Запрос пропущенного бэклога после длительного оффлайна
POST /api/v1/messages/send       --> Fallback отправка сообщений (если WebSocket недоступен)
GET  /api/v1/devices             --> Список подключенных устройств пользователя
```

---

### 2.2 Операции только через WebSocket

```
WS /ws/v1/connect                --> Постоянное живое соединение
  ├── client_hello / server_hello --> Handshake & Auth сессии
  ├── message_push                --> Мгновенный push входящего сообщения получателю
  ├── ack_event (delivered/read)  --> Передача сетевых статусов прочтения/доставки в реальном времени
  ├── ping / pong                 --> Heartbeat keepalive каждые 15 секунд
  └── session_terminated          --> Системное уведомление сервера о завершении сессии
```

---

## 3. Правила переключения и Fallback (Degraded Mode)

```mermaid
flowconfig
graph TD
    A[Попытка отправки сообщения] --> B{WebSocket в состоянии CONNECTED?}
    B -- Да --> C[Отправка через WebSocket envelope]
    B -- Нет --> D{REST API доступен?}
    D -- Да --> E[Отправка через REST POST /api/v1/messages/send]
    D -- Нет --> F[Сохранение в локальную оффлайн-очередь PendingQueue]
```

1. **Режим по умолчанию:** Если WebSocket активен (`CONNECTED`), все живые входящие/исходящие события передаются через WS.
2. **Degraded Mode (WS упал, REST работает):** Клиент может выполнять отправку сообщений через `POST /api/v1/messages/send`. Сообщение сразу сохраняется на сервере, а получатель увидит его при реконнекте к WS или при периодическом pull.
3. **Offline Mode (Сеть отсутствует):** Сообщение сохраняется в локальной оффлайн-базе (`PendingQueue`) до восстановления интернет-соединения.
