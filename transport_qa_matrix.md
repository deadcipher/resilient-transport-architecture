# Transport QA Test Matrix

В данной матрице собраны обязательные проверочные сценарии для тестирования сетевого слоя на устойчивость, реконнект, обработку ошибок и синхронизацию бэклога.

---

## Матрица тестовых сценариев

| ID | Категория | Сценарий | Ожидаемый результат | Автоматизировано |
| :--- | :--- | :--- | :--- | :---: |
| **TC-01** | Connect | Cold start с валидным токеном | Успешный `client_hello` → `server_hello` → переход в `CONNECTED` | ✅ |
| **TC-02** | Connect | Попытка входа с невалидным/просроченным токеном | Получение `error_event` (AUTH_EXPIRED), переход в `DISCONNECTED` | ✅ |
| **TC-03** | Send | Отправка сообщения при стабильном WS | Сообщение доставлено на сервер, получен `ack_event (accepted)` | ✅ |
| **TC-04** | Disconnect | Принудительное закрытие WS со стороны сервера | Переход клиента в `RECONNECTING`, старт Exponential Backoff | ✅ |
| **TC-05** | Reconnect | Восстановление связи через 3 секунды | Автоматический reconnect без участия пользователя | ✅ |
| **TC-06** | Offline | Отправка сообщения без доступа к сети (Offline) | Сообщение попадает в `PendingQueue`, UI не блокируется | ✅ |
| **TC-07** | Offline Flush | Появление сети после оффлайна | Автоматический сброс очереди `PendingQueue`, очистка отправленных | ✅ |
| **TC-08** | Dedup | Повторная отправка того же `client_request_id` | Сервер возвращает `ack_event (accepted)`, дубликат не создается | ✅ |
| **TC-09** | Heartbeat | Отсутствие ответов `pong` в течение 20 секунд | Принудительное закрытие сокета со стороны клиента и реконнект | ✅ |
| **TC-10** | Backlog | Получение бэклога после длительного оффлайна | Успешный забор пропущенных пакетов через `/sync/backlog` | ✅ |
| **TC-11** | Degraded | Отправка сообщения через REST при упавшем WS | Сообщение успешно уходит через POST-эндпоинт REST API | ✅ |
| **TC-12** | Version | Версия протокола клиента не поддерживается сервером | Получение `PROTOCOL_VERSION_MISMATCH` и корректный останов | ✅ |
